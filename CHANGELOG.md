# Changelog

All notable changes to the `@arcships` package family are documented in this file.

## [0.7.0] - 2026-11-18

### OpenDocument text view-only import (#144)

- `@arcships/docx-core` now reads OpenDocument text (`.odt`, `.ott`, `.odm`, `.otm`, `.oth` and flat `.fodt`) through the same model-building entry points as DOCX. The reader detects the ODF `mimetype` from the ZIP container (falling back to a deflated `mimetype` entry) or from the flat XML `office:mimetype`, validates the archive, XML depth/entity rules, entry/byte budgets and embedded image pixels before parsing, then converts `content.xml`/`styles.xml` into headings, character formatting, hyperlinks, bullet/numbered lists, tables with row/column spans, inline images and page setup. The model records `metadata.sourcePartNames.document = "content.xml"` and has no Word package; `isOpenDocumentModel(model)` reports it.
- `importDocxBuffer()` and the Worker/main-thread runtime auto-detect the format; `buildDocModelFromBytes()` keeps the upstream contract and returns the empty package for OpenDocument inputs. `parseDocx()` remains OOXML-only and rejects OpenDocument text with an explicit "OpenDocument text has no Word package" error.
- `@arcships/vue-docx` accepts the OpenDocument extensions in its viewer picker, editor import and drag-and-drop policy, exposes `OPEN_DOCUMENT_VIEW_ONLY_REASON`, `isOpenDocumentTextFileName()`, `isSupportedDocumentFileName()` and the supported extension/MIME lists. `DocxViewer` shows a visible `docx-view-only-reason` banner (`data-view-only="true"`) and disables download; `DocxEditor` renders the reason, keeps the surface non-editable through `DocxEditorController.viewOnlyReason`, rejects every model-changing transaction, and refuses `exportDocx()`, `getDocxBytes()` and `getDocxBlob()`. Word OOXML behaviour is untouched.
- Add `tests/fixtures/docx/opendocument/sample-html-features.odt` and `.fodt` (the upstream packaged/flat fixture pair) plus `tests/unit/docx-open-document.test.mjs` (packaged/flat parity, headings/formatting/lists/tables/images/page setup, cloning, `parseDocx` rejection, non-text ODF rejection and XML/input budgets) and `tests/component/docx-open-document.test.mjs` (public file policy, viewer banner and disabled download, real `.odt` upload view-only, `.docx` unchanged, editor edit/export refusal); extend the file-handling policy test and register both suites in `scripts/ci/run-suite.mjs`. Update the file-format support plan, DOCX guide, package READMEs, public API contract and demo copy.

### PDF outline/bookmarks, page labels and thumbnails (#103)

- `PdfRenderRuntime` gained two optional navigation capabilities. `getOutline(document)` maps the EmbedPDF bookmark tree into `PdfOutlineItem[]`: titles and nesting are preserved, in-document destinations become a 0-based `pageIndex`, URI actions keep their URL, and targets outside the document (remote go-to, launch) are dropped instead of producing a dead jump. `getPageLabels(document)` returns one display label per page. Both are optional, so injected runtimes that only raster pages simply show no outline.
- `PdfSurface` reads both after opening a document. When the document has bookmarks it renders an ARIA tree in a navigation rail beside the (unchanged) page scroller: `data-testid="pdf-surface-outline"` with one `pdf-outline-item` per visible entry. `↑`/`↓` move the roving focus, `→` expands or enters the first child, `←` collapses or returns to the parent, `Home`/`End` jump to the first/last visible entry, and `Enter`/`Space` activate an entry. Mouse users click a title to navigate (expanding branches on the way) or click the chevron to expand/collapse only. Activating a page entry scrolls to that page and updates the active page; URI entries emit `outlineActivate` with a sanitized URL (or `blocked: true`). `showOutline` defaults to `true`; documents without bookmarks show no panel.
- The viewer's thumbnail pipeline is now the shared `usePdfThumbnails()` composable behind the shared `PdfThumbnailStrip` component, so `PdfViewer` and `PdfSurface` use the same bounded worker pool, generation/abort guards and object-URL lifetime. Both viewers show the strip by default; `PdfSurface` exposes `showThumbnails` to opt out and, when shown, renders the strip with `data-testid="pdf-surface-thumbnails"` / `pdf-surface-thumbnail`. Both strips label pages with `getPageLabels()` output (`1`, `iv`, `A-3`) and highlight the current page; clicking a thumbnail scrolls to it.
- `/PageLabels` is read directly from the verified PDF bytes because the EmbedPDF worker engine does not forward `FPDF_GetPageLabel`. The byte-level parser follows indirect trees, `/Kids` and `/Nums` ranges, `/S` decimal/roman/letter styles, `/P` prefixes (including UTF-16BE hex strings) and `/St` start numbers, and falls back to decimal page numbers for pages before the first range, documents without labels and labels compressed into object streams. Only the parsed labels are retained; the document buffer is not kept.
- Add `tests/unit/pdf-page-navigation.test.mjs` (outline target mapping/filtering, inline and indirect page-label trees, kids/letter styles, fallbacks, closed-document and abort guards) and `tests/component/pdf-navigation-aids.test.mjs` (outline rendering and optional capability, tree keyboard semantics, page and URI activation, thumbnail strip following scrolling and outline navigation, viewer strip sharing page labels); register both in `scripts/ci/run-suite.mjs` and document the behaviour in the PDF guide, keyboard guide, public API contract and the `PdfSurface` entry docs.

### XLSX legacy indexed colours (#105)

- Legacy OOXML indexed colours are now resolved instead of falling through to the fallback black/transparent. `xl/styles.xml` is read for the workbook's `<colors><indexedColors>` list, and `buildThemePalette()` combines it with the ECMA-376 18.8.27 default palette (indices 0–63 plus the system foreground/background entries 64/65) into the new `XlsxThemePalette.indexedColors` map. Entries a custom palette omits keep the standard value.
- `resolveWorkbookColor()` handles `{ indexed }` and the engine's `{ colorType: "indexed", paletteIndex }` shape; the palette index wins over the engine's default-palette `hex` so a workbook override reaches the renderer. Tint uses the same HSL rule as theme colours, and out-of-range or non-integer indices stay unresolved instead of turning black. Because fills, fonts, borders, conditional formats, sparklines, thumbnails, print preview and the canvas/DOM grids all go through that resolver, indexed cells now paint their real palette colour.
- Add `test-data/corpus/xlsx-indexed-colors.xlsx` and `test-data/corpus/xlsx-indexed-custom-palette.xlsx` (generated by `scripts/fixtures/generate-xlsx-indexed-colors.py`) covering palette indices 0/9/10/22/55/63/64/65, indexed tints and indexed font colours, plus a workbook whose `indexedColors` overrides indices 8, 10 and 22. Add `tests/unit/xlsx-indexed-colors.test.mjs` (palette parsing, merge/fallback, tint, engine-shaped colours) and `tests/component/xlsx-indexed-colors.test.mjs` (the controller/DOM grid paints the standard and custom fills and font colours), register both in `scripts/ci/run-suite.mjs`, and document the resolution in the XLSX guide, public API contract and upstream alignment notes.

### PPTX playback v2 element targets, granular text, table cells and transition sounds (#117)

- **Granular text:** `p:txEl/p:charRg` now reaches the playback model as `PptxPlaybackEffect.characterRange` (inclusive character offsets, paragraph marks count as one character). The browser track index splits a targeted paragraph into word boxes (`data-pptx-text-run="word"`) containing character boxes (`data-pptx-text-run="char"`), each with paragraph-local `data-pptx-run-start`/`data-pptx-run-end`. A whole-word range targets the word box so shaping and line breaking stay word-like; a partial range targets the character boxes. Splitting is lazy (only for text that animates), idempotent, and leaves `textContent` unchanged. Capability reporting adds the stable codes `text:by-word` and `text:by-character` (strict) and `text:character-range-unavailable` (static) when the target has no readable text body.
- **Table cells:** table paragraph ranges are numbered in row-major cell order and resolve through `#cell:row:column` state keys. Row-span/col-span cells expand into the visual grid, merge continuation cells do not shift later columns, and per-cell paragraphs restart no longer collide. `p:bldGraphic`/`p:bldSub` build lists are reported as `table-build:<mode>` (static) because they only group explicit cell effects.
- **Chart and SmartArt element targets:** `p:oleChartEl` parses into `chartElement` (`chart`, `series`, `category`, `point-in-series`, `point-in-category`). A whole-chart target is strict (`chart:element`, `#chart:chart`); series/category/point targets are reported as `chart:series`, `chart:category` or `chart:point` (static) because the pinned renderer paints charts as one canvas. `p:subSp` and numeric `p:graphicEl/@id` resolve to the rendered child object key and execute SmartArt nodes (`smartart:node`, `group:sub-shape`); level-only targets report `smartart:level` (static).
- **Transition sounds and 3D transitions:** `<p:transition><p:sndAc>` parses into `PptxSlideTransition.sound` and plays through a dedicated audio stub with the same resolver, external-media policy and autoplay gate as media shapes; a blocked sound joins `blockedMediaIds` and `resumeBlockedMedia()` retries it. Capability code `transition:sound` is strict for embedded sounds and static for external or missing targets. 3D transitions (`cube`, `flip`, `switch`, `gallery`, …) always report `transition:3d:<kind>` static and never degrade to a fake 2D fade, even with `approximation="safe"`.
- Add `tests/unit/pptx-playback-v2.test.mjs` (parser/compile coverage for word/character ranges, unavailable text bodies, table cells, chart series/category/points, SmartArt nodes/levels, transition sounds and 3D transitions, plus controlled fixture hashes/XML markers), `tests/unit/pptx-text-runs.test.mjs` (word/character boxes, idempotent splitting, table grid expansion, per-cell state application and element target resolution), `tests/unit/pptx-transition-sound.test.mjs` (resolver wiring, blocked-sound gating, retry, pause/resume and source release) and extend `tests/unit/pptx-core.test.mjs` to load `track-player.ts` through the shared TypeScript resolve hook. Add `scripts/fixtures/generate-pptx-v2-fixtures.mjs` and four `controlled` fixtures (`text-by-word.pptx`, `chart-series.pptx`, `table-cells.pptx`, `transition-sound.pptx`) derived from `text-by-paragraph.pptx`; they are registered in `tests/fixtures/pptx/playback/manifest.json` with hashes, focus slides, expected capability codes and XML markers, and must be re-saved in desktop PowerPoint before becoming `ready`. Document the stable capability codes and target-key formats in the PPTX playback API, compatibility, implementation, roadmap and development guides.

### RTL/bidi support for XLSX sheets, DOCX paragraphs and PPTX text (#112)

- **XLSX:** `parseSheetState()` now reads `<sheetView rightToLeft="1">` into `WorkbookSheetState.rightToLeft`, and `XlsxSheetData.rightToLeft` carries the same flag through the main-thread and Worker sheet builders. The canvas grid mirrors the column axis: column A sits at the right edge, column headers follow their columns, frozen columns pin to the right-hand strip (frozen rows stay at the top), the scrolling pane starts left of the pinned strip, and `scrollToCell()` uses the mirrored scroll range. Text alignment is mirrored like Excel (general/left becomes right, explicit `center` unchanged) and overflow text spills leftwards. Hit testing, header hit testing, drag-selection, double-click editing, column resize (including the inverted drag delta) and the `←`/`→` keys all use the mirrored coordinates; `hitTestSheetPoint()` keeps `xOffset` measured from the visual left edge. Inline editor, comment popover, validation hints/dropdown, AutoFilter buttons, page-break overlay and the fill handle are placed through the same pane geometry, so none of them cross the freeze line. The mirroring rules live in pure helpers in `grid-pane-geometry.ts` (`axisLayoutOffset()`, `axisLayoutBoundary()`, `axisLayoutScroll()`, `mirrorBodyOffset()` and RTL-aware `resolvePaneViewPoint()` / `resolvePaneOverlayRect()`). Row headers stay on the left; rows are not mirrored.
- **DOCX:** `ParagraphStyle.direction` (from `w:bidi` / `w:rtl`) now reaches the DOM as `dir="rtl"` / `dir="ltr"` on the paragraph host and on table-cell paragraphs. Combined with the existing `direction` + `unicode-bidi: embed` CSS and `w:jc` start/end mapping, an RTL paragraph renders right-aligned with bidi punctuation order. Paragraphs without a bidi mark are untouched.
- **PPTX:** the renderer already paints `a:pPr/@rtl="1"` paragraphs with `direction: rtl`; `applyPptxParagraphDirection()` now forwards that decision to the rendered paragraph as `dir` plus `data-pptx-paragraph-direction`, and `PptxStage` CSS honours it. Playback capability reporting adds `text:rtl-paragraph` (`strict`) for mirrored paragraphs and `text:rtl-columns` (`static`, with a reason) when `a:bodyPr/@rtlCol` asks for a column order the renderer does not mirror. Slides without RTL text keep their capability counts unchanged.
- Add `tests/unit/xlsx-right-to-left.test.mjs` (rightToLeft parsing, mirrored offsets/boundaries/scroll, RTL pane hit testing and overlay clipping, grid wiring), `tests/component/xlsx-grid-rtl.test.mjs` (painted header/cell positions, hit testing, frozen-column mirroring with scroll, selection tint and fill-handle placement), `tests/unit/pptx-rtl.test.mjs` (parser features, DOM direction forwarding, marker wiring) and `tests/component/docx-rtl.test.mjs` (dir attribute, right/start alignment, LTR paragraphs, table-cell wiring); register all four in `scripts/ci/run-suite.mjs` and document the behaviour in the XLSX, DOCX and PPTX guides.

### XLSX DOM render fallback (#107)

- The grid was canvas-only: cells existed only as painted pixels, so browser find, native text selection and the accessibility tree could not see a value, and a canvas that could not be created left no fallback. `XlsxViewer`, `XlsxSheetSurface` and `XlsxGrid` now accept `renderMode: "canvas" | "dom"` (default `"canvas"`); `"dom"` renders the visible window as real `role="row"` / `role="gridcell"` elements with the cell text as text nodes and no canvas at all. `XlsxGridRenderMode` is exported from the root entry.
- Both renderers share one model: the DOM layer reuses `resolveCanvasCellStyleInto` (fonts, fill, colour, alignment, wrapping, underline/strike, rotation and shrink-to-fit), the same workbook border widths/dashes, conditional data bars/colour scales/icon sets, hyperlinks, comments, sparklines, merged-region geometry, number-formatted display values and host `getCellStyle` overrides. The visible window includes the same ±240 px overscan and the frozen panes stay pinned, with the body and both header strips translated by the scroll offset instead of rebuilt on every scroll tick.
- The DOM layer only materialises the visible window (a row far below the viewport has no element), keeps text selection available (`user-select: text`, Alt+drag leaves the selection to the browser and Ctrl/Cmd+C then copies the selected text instead of the cell range), paints selection/cut/fill-preview/formula-reference outlines per freeze pane, and keeps the active cell's `aria-activedescendant` target inside the rendered window, falling back to the hidden a11y mirror only when the active cell is off-screen. Switching `renderMode` never recreates the scroll container, so the scroll position and the controller's selection survive DOM → canvas → DOM.
- The pure style/geometry mapping lives in `packages/vue-xlsx/src/components/grid-dom.ts` (`resolveGridRenderMode`, `canvasBorderEdgeCss`, `canvasCellStyleToCss`, `canvasCellTextStyle`, `richTextRunCss`, `gridDomSelectionStyle`, `resolveGridDomAxisWindow`, `resolveGridDomOutlineStyle`) and the presentational layer in `XlsxGridDomLayer.vue`. Add `tests/unit/xlsx-dom-render.test.mjs` (mode normalisation, border widths/dashes, font/fill/alignment mapping, shrink and merge gridlines, text clipping/rotation, rich runs, frozen axis windows, outline clipping) and `tests/component/xlsx-dom-render.test.mjs` (semantic gridcells and DOM headers, visible-window-only rendering, scrolled text selection surface, formatted/styled cells, conditional formats, host style overrides, active-cell mirror, mode switching with scroll/selection preserved, Alt+drag, viewer default and prop forwarding); register both in `scripts/ci/run-suite.mjs` and document the mode in the XLSX guide, custom-surface guide and public API contract.

### XLSX fill handle and double-click axis auto-fit (#108)

- The grid now draws Excel's fill handle at the selection's bottom-right corner (`data-testid="xlsx-fill-handle"`, `data-fill-target` on the grid root). It is a 7 px square centred on the corner, positioned through the same pane geometry as the editor and popovers, so it follows scrolling, zoom and frozen panes and disappears when the corner scrolls out of its pane instead of sticking to the viewport edge. Read-only and protected sheets show no handle.
- Dragging the handle previews the target range with a dashed gray outline and calls `controller.fillSelection(targetRange)` on release, so the existing tiling rules apply unchanged: the source pattern repeats (`offset % sourceSize`), relative formula references shift by the drag distance (`$` anchors stay), and styles are copied. The whole fill is one history entry, and the selection grows to the filled range. Dragging only previews — a pointer that stays on the source or a `pointercancel` writes nothing.
- Double-clicking a column or row header boundary auto-fits that axis. Column widths are measured from the formatted display values with the very fonts `drawCellText` paints with (base style plus per-run rich-text fonts, rotated text measured by its rotated bounds), plus the paint path's 5 px cell padding and 2 px rounding room; row heights use the same greedy wrap into the cell's current column width and add the 4 px vertical chrome. Empty axes keep their width, merged cells are skipped, and each axis scans at most 20 000 used cells.
- Auto-fit goes through `controller.resizeColumn()` / `controller.resizeRow()`, so it is one undo entry, honours read-only and sheet protection, and clamps to Excel's column (32–1800 px) and row (18–546 px) ranges. Without a Canvas (SSR, the test renderer) measurement falls back to `estimateAutofitTextWidth()`.
- The drag semantics and the measurement live in pure, canvas-free helpers (`resolveFillTargetRange()`, `normalizeFillRange()`, `fillRangesEqual()`, `resolveFillHandleBox()` in `grid-fill-handle.ts`; `measureAutofitTextWidth()`, `countAutofitLines()`, `measureAutofitContent()`, `resolveAutofitColumnWidth()` and `resolveAutofitRowHeight()` in `grid-paint.ts`) that take a measure callback.
- Add `tests/unit/xlsx-fill-handle-autofit.test.mjs` (drag targets up/down/left/right/diagonal and reversed sources, handle centring, painted-text and rich-run measurement, wrapped line counts, rotated boxes, fitted sizes, zoom and Excel's clamps) and `tests/component/xlsx-fill-handle-autofit.test.mjs` (handle DOM, position and scroll hiding, read-only, drag preview → fill → single undo, cancel, column/row boundary double-click with recorded resize requests, header clicks that neither resize nor edit, and the unchanged cell-body double-click editor); register both in `scripts/ci/run-suite.mjs` and document the behaviour in the XLSX guide. The grid's `aria-label` for the handle comes from the shared catalog (`grid.fillHandle`).

### XLSX selection status bar (#111)

- `XlsxViewer` now renders a selection status bar under the sheet tabs (opt out with `showStatusBar="false"`): cell/range address, non-empty count, numeric count when it differs, sum, average, min/max, and a `Selected`/`Filtered` note. Totals use the first numeric cell's number format, so currency and percentage selections keep their units; date, time and text formats fall back to General.
- The summary reads only the current selection, bounded by `XLSX_SELECTION_STATS_CELL_LIMIT` (10,000 cells) with a `…` marker when the range is larger. AutoFilter-hidden rows are excluded from the totals and mark the selection as `Filtered`. Main-thread viewers read the active worksheet directly; Worker-backed viewers call `controller.getSelectionStatsAsync()` for an aggregate computed inside the Worker, so selected cells never cross the thread boundary.
- `xlsx-core` exports `summarizeSelectionValues()`, `XlsxSelectionSummary`, `XlsxSelectionStatsQuery` and the shared limit; `vue-xlsx` exports `XlsxStatusBar`, `useXlsxSelectionStats()`, `formatSelectionStatValue()` and the `showStatusBar` prop. Add `tests/unit/xlsx-selection-stats.test.mjs` (summary arithmetic, truncation and compensated totals), `tests/unit/xlsx-selection-status.test.mjs` (General/number/currency/percent/scientific formatting), Worker coverage in `tests/unit/xlsx-worker.test.mjs`, and `tests/component/xlsx-status-bar.test.mjs` (A1:A10 totals, number formats, sheet switching, filtered rows, the 10,000-cell cap, locale copy and the Worker aggregate); document the behaviour in the XLSX guide, custom-surface guide and public API contract.

### View modes: DOCX single/spread, PDF page layouts, PPTX slide sorter (#110)

- DOCX gained `viewMode` on `DocxViewer`, `DocxDocumentSurface` and `DocxViewerRoot`: `continuous` (one page per row, unchanged), `single` (one page mounted at a time, the scroll offset snaps to the nearest page boundary after scrolling settles) and `spread` (two pages side by side, paired (1,2), (3,4), a trailing lone page centered across the spread). All three modes reuse the same scroll space, so page offsets, the pagination scroll anchor, bookmark and search navigation are unchanged; `DocxViewer` re-scrolls to the current page when the mode changes instead of rewinding to page 1, and a spread keeps the selected page in its pair through `visiblePageRange`. The annotation gutter is part of each page footprint, so spreads stay centered with comments or balloons visible. Context-menu and text-selection hit testing now resolve the left/right page of a spread by x instead of only by y.
- DOCX also gained `fitMode` (`width` / `page`) with `defaultFitMode`, closing the fit-width vs fit-page gap: `page` fits the whole sheet (the tighter of width and height), while `fitWidth` stays as the compatible boolean. The viewer toolbar exposes segmented controls for the three layouts (`docx-view-mode-continuous|single|spread`) and for both fit modes (`docx-fit-width`, `docx-fit-page`); `update:viewMode` and `update:fitMode` let hosts own the state, and choosing a zoom level (or gesture zoom) hands control back to the zoom factor. The root exposes `data-docx-view-mode`, `data-docx-fit-mode` and per-page `data-docx-page-number`/`data-docx-page-row-index`.
- PDF unified `PdfSurface` and `PdfViewer` behind one `pageLayout` prop (`continuous` / `single` / `spread`, plus `defaultPageLayout` and `update:pageLayout` on the viewer). `PdfSurface` now paints its pages in a CSS grid whose column template, gaps and row offsets come from `resolvePdfPageLayoutMetrics()`, so spreads place two pages side by side while continuous/single keep the offsets they had. Single-page mode rasterizes only the snapped page and snaps the scroll offset to the page top; the rasterization window follows the visible rows in every mode. `PdfViewer` renders the same three layouts: `continuous` stacks every page inside the scroll frame and lazily rasterizes only the active one (sized, numbered placeholders fill the rest), `spread` rasters the facing page into its own bitmap and keeps its own page number, and switching layouts keeps the active page by scrolling to the row it now occupies.
- `@arcships/vue-docx` exports the layout primitives (`resolveDocxViewLayout`, `docxPageRows`, `docxRowIndexAtOffset`, `docxRowIndexForPage`, `docxRowsInViewport`, `docxSnapTopForRow`, `docxPageAtPoint`, `docxSpreadStepPage`, `isDocxSpreadMode`, `normalizeDocxViewMode`, `normalizeDocxFitMode`, `DOCX_VIEW_MODES` and their types) and `@arcships/vue-pdf` exports the PDF equivalents (`resolvePdfPageLayoutMetrics`, `pdfPageLayoutRows`, `pdfRowIndexAtOffset`, `pdfPageIndexAtOffset`, `pdfSnapTopForRow`, `pdfPageAtPoint`, `pdfRowsInViewport`, `pdfSpreadPagePair`, `pdfSpreadStepPage`, `normalizePdfPageLayout`, `isPdfSpreadLayout`, `PDF_PAGE_LAYOUTS` and their types) for hosts that build their own surface.
- PPTX gained a slide-sorter grid in browse mode: `viewMode` (`single` / `sorter`), `defaultViewMode`, an `update:viewMode` event and the `pptx-view-mode-single` / `pptx-view-mode-sorter` toolbar buttons. The sorter reuses `PptxThumbnail` behind the shared intersection gate, mounts only the rows around the scroll position (equal-height spacers above and below keep the scroll length exact), keeps browse keys scrolling the grid instead of changing slides, keeps the selected slide highlighted and selected when switching layouts or clicking a cell, and scrolls the current slide into view when it opens. The sidebar is hidden while the grid is open, and `data-testid="pptx-sorter"`, `data-testid="pptx-sorter-item"`, `data-slide-index` and `data-active` expose the grid state.
- Add `tests/unit/docx-view-mode.test.mjs`, `tests/unit/pdf-page-layout.test.mjs`, `tests/component/docx-view-modes.test.mjs` (spread pairs and page numbers, single-page snapping, spread hit testing, mode switching keeping the current page, fit-page vs fit-width), `tests/component/pdf-view-modes.test.mjs` (surface spread grid and page numbers, single-page rasterization, spread context-menu hit testing, viewer spread facing page, continuous mode and layout switching) and `tests/component/pptx-slide-sorter.test.mjs` (grid contents, selection sync across layouts, row windowing and browse keys), register them in `scripts/ci/run-suite.mjs`, and document the behaviour in the three viewer guides and the public API contract.

### XLSX built-in chart style palettes (#142)

- Classic charts that carry a `<c:style>` value (1–48, or 101–148 from Excel 2010+) now use Excel's built-in series palette instead of always falling back to theme accent1–6. A new `builtin-chart-styles` module resolves the style to its theme-colour palette, applies DrawingML tint/shade in linear RGB, and reproduces the grayscale, six-grey, monochrome-accent and colourful variants (including the extra brightness groups for charts with more than six series).
- Built-in palettes are used only when the chart has no `chartColorStyle` part (`raw.hasCustomChartColorStyle`); explicit series `spPr` fills still win, and series/points that carry a `fillImage` keep their picture fill. The selected palette feeds `chartColorPalette` and every series/marker default, and type groups keep their own offset. 3-D surface charts keep their dedicated contour palette while 3-D style 34–40 walls, floors and major gridlines now come from the same built-in surface style; `XlsxChartAxis.majorGridlineColor` carries the resulting gridline colour to custom renderers.
- Add `tests/unit/xlsx-chart-builtin-styles.test.mjs` (style 2/34/41/102 palettes, grayscale theme, six-grey sequences, custom color-style precedence, explicit series fills, surface walls/gridlines and export/reload through both the chart parts and the engine save path); register it in `scripts/ci/run-suite.mjs` and document the behaviour in the XLSX guide.

### XLSX preset shape geometry and connector decorations (#143)

- Worksheet drawings no longer collapse every non-ellipse `a:prstGeom` to a rectangle. `xlsx-core` now carries the ECMA-376 preset geometry table (right/left/up/down arrows, chevrons, stars, wedge/border/distinct callouts, flow-chart shapes, braces/brackets, moons, clouds, gears, arcs, chords, funnels and the rest), and `buildPresetShapePath(geometry, adjustments, { width, height })` returns `{ path, viewBox }` in the shape's pixel space. `a:avLst` guides are fed in as DrawingML 1/100000 values, so `adj1`/`adj2` resize an arrow exactly like Excel.
- `XlsxShape.geometry` keeps the raw `prst` name, and parsed shapes now also carry `svgPath`/`svgViewBox` for preset geometry (custom `a:custGeom` keeps its own path and view box). `XlsxDrawingLayer` rebuilds the preset path from the live rect (including zoom and resize previews) instead of stretching a stale path, so arrows, stars, callouts and flow-chart shapes stay recognisable at any size; only an unknown `prst` falls back to a rectangle.
- Connectors are open paths and are never filled (`isStrokeOnlyShapeGeometry()` covers `line`, `straightConnector1`, `bentConnector2`–`5`, `curvedConnector2`–`5`, arcs, braces and brackets). `a:ln@w`, `a:prstDash` (`dash`, `dot`, `lgDash`, `lgDashDot`, `sysDash`, `sysDashDot(–Dot)`, …) and `a:headEnd` / `a:tailEnd` (`triangle`, `stealth`, `arrow`, `diamond`, `oval`) now render as SVG dash arrays and start/end markers scaled with the line width.

### Drag-and-drop file import for XLSX, PDF and PPTX (#109)

- Only the DOCX viewer accepted dropped files; XLSX, PDF and PPTX had no `dragenter`/`dragover`/`drop` handlers, so dropping a workbook, PDF or deck did nothing. The DOCX behaviour is extracted into `useFileDrop` in `@arcships/vue-ui` — one implementation of the accept list, the drag-over depth, the outline and the rejected-drop feedback for all four formats. `accept` matches lower-case extensions and MIME types, `onFile` receives the first supported file, `onReject` receives the rest, and `enabled` can be a getter (DOCX only accepts drops while editable).
- The drag depth follows `dragenter`/`dragleave` nesting; `dragover` only sets `dropEffect` and never increments the counter, so the outline cannot stick after a drag leaves (the DOCX multi-page shell bug, #27). A drag that ends outside the viewer clears through a window `dragend`/`drop` listener, and leaving for a descendant is ignored. `FILE_DROP_OUTLINE` (`3px dashed #2563eb`) is the shared outline, `isSupportedDropFile()`/`fileDropExtension()` are the reusable pure checks, and the viewer roots expose `data-file-drop-active` while a file is over them.
- `XlsxViewer` drops a workbook through the controller: `XlsxViewerController.loadFile(source, fileName?)` (new public method, `XlsxLoadFileSource`) reads a `File`/`Blob`/`ArrayBuffer` and runs the existing loading watcher, so a dropped workbook gets the same size limits, deferred-load threshold, URL policy and Worker path as the `file` option. `XLSX_FILE_EXTENSIONS`/`XLSX_FILE_MIME_TYPES`/`XLSX_FILE_ACCEPT`/`isSupportedXlsxFileName()` are exported and also used by the demo file picker.
- `PdfViewer` and `PptxViewer` treat a dropped document as the effective source (`droppedSource` wins over `source`/`src` until the host changes them) and load it through the same `load()` / `usePptxDocument` pipeline as a picked file. All three viewers emit `fileDrop(file)` for hosts that keep their own file label in sync, and a host-owned source supersedes the dropped one.
- A rejected drop never reaches the loader. DOCX keeps its status-bar message; the other viewers render a `role="alert"` banner above the document (`xlsx-drop-error`, `pdf-drop-error`, `pptx-drop-error`) with the localized `unsupportedDrop` copy added to the shared catalog in English and Simplified Chinese. `PDF_FILE_*`/`PPTX_FILE_*` constants and `isSupportedPdfFileName()`/`isSupportedPptxFileName()` mirror the XLSX accept policy.
- Add `tests/component/file-drop-import.test.mjs`: composable depth/outline/accept-list tests, plus XLSX (drop loads a real workbook through `loadFile()`, wrong type shows the message and keeps the previous workbook), PDF (fake runtime — second `openDocument`, rejected drop, outline clears) and PPTX (fake session — second `open`, the dropped `File` is the source, rejected drop). ### XLSX cell text rotation and shrink-to-fit (#141)

- Cell text rotation and shrink-to-fit were parsed into `styleById[*].alignment` but never used, so 45°/90°/180° headers stayed horizontal and long values overflowed narrow columns. `parseSheetState()` now records the cells whose explicit style carries `textRotation` or `shrinkToFit` in `WorkbookSheetState.cellTextLayouts` (A1 keyed) and passes it through both the main-thread and Worker sheet lists.
- The canvas grid resolves rotation with Excel's semantics: 0–90° is counter-clockwise and 91–180° is clockwise, so 45° paints at −45°, 90° at −90° and 180° at +90°. Rotated text is anchored by its rotated bounds (the occupied width/height swap at 90°), measured in its own coordinate space, and clipped to the cell rectangle, so it cannot paint over the neighbouring cell that hit-testing still attributes to the grid. The existing horizontal overflow pass is disabled for rotated and shrink-to-fit cells.
- Shrink-to-fit binary-searches the canvas font from the base size down to Excel's 0.4× floor using the measured text width, then paints the full value inside the cell (rich-text runs scale with the cell font). The grid, sheet thumbnails and the print-preview DOM path reuse the same `resolveSpreadsheetTextRotation()`, `resolveRotatedTextFitWidth()`, `resolveRotatedTextBounds()`, `resolveRotatedTextCenter()` and `resolveShrinkToFitFontSize()` helpers, so a 45°/90°/180°/shrink-to-fit header looks the same in all three surfaces at any zoom.
